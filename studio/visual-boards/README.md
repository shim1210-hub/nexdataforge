# Visual Design Boards

Visual Design Board는 Design Language를 한눈에 비교하고 검토할 수 있도록 시각 자료를 주제별로 모아두는 작업 보드다. 아직 이미지가 없는 경우에도 보드의 목적, 규격, 상태, 다음 작업을 README로 관리한다.

## 왜 필요한가

문서만으로는 색의 관계, 타입의 계층, 컴포넌트의 밀도와 상태 변화를 빠르게 비교하기 어렵다. Board는 팀의 공통 판단 기준을 시각적으로 고정하고, 프로젝트 간 차이와 재사용 가능한 패턴을 발견하게 한다.

## 다른 문서와의 차이

- **Design Language**: 의미와 사용 원칙을 정의한다.
- **Design System**: 원칙을 토큰·컴포넌트·코드 규격으로 구현한다.
- **Project Design Book**: 특정 제품의 흐름과 화면에 적용한다.
- **Visual Board**: 원칙과 구현 후보를 시각적으로 비교·검토한다.
- **Mockup**: 특정 화면의 사용자 흐름과 결과를 보여준다.

## 보드 규칙

모든 보드는 `A4` 또는 `B5` 중 하나를 선택한다. A4는 비교·프레젠테이션·데스크톱 검토용, B5는 모바일 중심의 작고 빠른 검토용이다. 한 보드 안에서는 규격을 섞지 않는다.

각 보드는 목적, 대상, 규격, 현재 버전, 마지막 수정일, 적용 프로젝트, 실제 이미지 수, 미해결 항목을 기록한다. 실제 이미지가 없으면 파일을 만들지 않고 README에 `이미지 없음`과 다음 작업을 기록한다.

## 버전 규칙

초안은 `v0.1`, 첫 검토본은 `v0.2`, 구현 기준본은 `v1.0`으로 관리한다. 큰 구조 변경은 첫 번째 숫자를 올리고, 내용·배치 수정은 두 번째 숫자를 올린다.

## 파일명 규칙

실제 자료는 `{board}-{topic}-v{version}.{ext}`를 사용한다. 예: `bidme-buttons-v1.0.png`. 프로젝트와 화면이 있는 경우 `{project}-{screen}-{board}-v{version}.{ext}`를 사용한다. 임의의 이미지나 placeholder 파일은 생성하지 않는다.

## 프로젝트 연결

공통 보드는 모든 프로젝트가 참조하고, 프로젝트별 변형은 Project Design Book에서 해당 보드와 예외 이유를 링크한다. 현재 첫 연결 대상은 `projects/bidme/README.md`다.
